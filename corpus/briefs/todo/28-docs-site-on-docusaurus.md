# Task 28: Move the docs site from Starlight to Docusaurus

## Context

On 2026-10-18 the owner decided to move every project's docs site from Astro
Starlight to Docusaurus. `docs-site/` (`@bots/docs-site`, served at
`/just-a-bot/docs/`) is one of them.

The recipe is written and verified. The `corpus-docs-site` skill
(personal-skills v0.31.0, source in
`~/projects/my-personal-skills/skills/corpus-docs-site/`) now scaffolds
Docusaurus 3.10, and `references/migrating-from-starlight.md` beside it holds
the file, config and content maps plus ten gotchas, each hit during a real
port. **Read that guide first.** The files this brief tells you to copy are in
the same folder. If the installed plugin is older than v0.31.0, read them from
the source path.

What the site has today (2026-10-18):
- base `/just-a-bot/docs/` (`DOCS_BASE ??`), 11 sidebar links, with TypeDoc
  ("@bots/shared") opening in a new tab;
- **dark only**: `src/styles/theme.css` (227 lines, 38 `--sl-*` tokens, Archivo
  + JetBrains Mono via `@fontsource`) gives light and dark the same palette.
  No `Theme*.astro` overrides, so Starlight's toggle is shown and does nothing;
- one authored page, `index.mdx` (a `Diagram`, a raw `<dl>`), plus 31
  `:::note` banners across the generated pages;
- `scripts/sync-corpus.mjs` with **two passes**: a hand-kept list of 8 corpus
  pages → `src/content/docs/wiki/`, and every `docs/**/*.md` →
  `src/content/docs/manual/`, where a folder's `README.md` becomes the folder's
  page (`discord/trivia/README.md` → `manual/discord/trivia.md`);
- the generated manual (23 files) is **committed**. The script's header says
  generated files are gitignored, but `.gitignore` only lists `wiki/`;
- TypeDoc (`../shared/src/index.ts` → `public/reference`), and
  `scripts/build-diagrams.mjs` (one archify diagram).

**Built through Docusaurus on 2026-10-18.** The 10 corpus pages built through
the new sync in `markdown.format: 'detect'` mode. In MDX mode the corpus does
not compile. The manual pass, ported as it is, fails the build. **42 links in
the 23 manual pages do not resolve.** On the live Starlight site those are dead
links today; Docusaurus refuses them. They fall into three kinds:
- links to a folder's `README.md`, which the pass renamed to the folder's page
  (`rpg/README.md`, `wordle/README.md`, `trivia/README.md`, `jukebox/README.md`,
  …), including `../discord/README.md` from `common/architecture.md`;
- links out of `docs/` into the corpus (`../corpus/index.md`,
  `../../corpus/wiki/decisions.md`) or to the repo `README.md`
  (`../README.md`);
- a few plain sibling links (`setup.md`) that the rename also broke.

## What to do

1. **Baseline.** `npm run docs -w @bots/docs-site`, then save
   `(cd docs-site/dist && find . -name index.html | sort) > /tmp/jab-routes-before.txt`.
2. **Config.** Write `docusaurus.config.ts` from the skill's reference. Set
   baseUrl `process.env.DOCS_BASE ?? '/just-a-bot/docs/'`,
   `trailingSlash: true`, `routeBasePath: '/'`, `markdown.format: 'detect'`,
   local search, and the GitHub navbar item. **colorMode = dark only**:
   `{ defaultMode: 'dark', disableSwitch: true, respectPrefersColorScheme: false }`.
   The useless toggle goes. Port the 11-link sidebar to `sidebars.ts`. The
   manual section can be `{ type: 'autogenerated', dirName: 'manual' }`.
   TypeDoc becomes `{ type: 'link', href: 'pathname:///reference/' }`.
3. **package.json** per the guide: no `"type": "module"`, keep the
   `browserslist`, and add `start`/`docs`/`typecheck`. Keep `typedoc` and the
   two `@fontsource` packages. Drop `astro`, `@astrojs/starlight`, `cookie` and
   `sharp`; grep the repo first for any other importer.
4. **Content.** `src/content/docs/index.mdx` → `docs/index.mdx` with `slug: /`.
   Use the skill's `Diagram.tsx`. `git mv public/diagrams static/diagrams`, and
   point `build-diagrams.mjs` at it.
5. **Sync, corpus pass.** Use the skill's `sync-corpus.mjs` (discovery, links
   resolved per source page, `docs/wiki/` output) with `GITHUB_REPO` set to this
   repo's GitHub URL. The corpus has no cross-repo links. Discovery publishes
   two pages the old 8-page list left out, `decisions-removals` and
   `jukebox`. Publish them unless the owner wants either kept back (the
   script's `DENY` set).
6. **Sync, manual pass.** Keep the second pass and its README-to-folder rename,
   writing to `docs/manual/`, but give it the same link resolution the corpus
   pass has. Resolve each relative link against the source file's directory
   under `docs/`. Then:
   - a target that is another manual page becomes a relative file link to its
     **renamed** output (`X/README.md` → the folder's page);
   - a target in `corpus/wiki/` (or `corpus/log.md`) that the corpus pass
     renders becomes a relative file link into `docs/wiki/`;
   - anything else in the repo becomes a GitHub `blob/`/`tree/` URL;
   - images become `raw/` URLs, or are copied next to the page.
   Use the frontmatter key `toc_max_heading_level: 3`. One URL changes on
   purpose: Docusaurus treats a `README.md` as its folder's index, so the
   top-level `docs/README.md` becomes `/manual/` instead of `/manual/readme/`.
   Write it as `manual/index.md` so that is explicit, and point anything that
   linked `/manual/readme/` at `/manual/`. The nested READMEs are already
   renamed by the pass, so nothing else moves.
7. **Stop committing generated output.** Add `docs/manual/` and `docs/wiki/` to
   `docs-site/.gitignore`. The old `src/content/docs/manual/` goes with the
   rest of `src/content/`. Also in that file: `.astro/` → `.docusaurus/`,
   `public/reference/` → `static/reference/`.
8. **Theme.** Port `theme.css` to `src/css/custom.css`, with the dark palette on
   `:root, :root[data-theme='dark'], :root[data-theme='light']`, mapped onto
   `--ifm-*` with the guide's tables (the skill's `references/custom.css`
   header). Keep the comment on why there is no light theme.
9. **Mentions.** Update the files listed under Files you OWN. The
   `decisions.md` line says the one build in the repo is the docs site's
   `astro build`. It stays true with `docusaurus build`, so change the command,
   not the decision.
