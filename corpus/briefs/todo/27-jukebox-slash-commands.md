# Task 27: Jukebox, part 3: the `/jukebox` command and its docs

## Context

Source: the Jukebox grilling with the owner, 2026-10-08. See the decision "Music
comes from atrium, signed in as the bot's own Ward account" in
[decisions.md](../../wiki/decisions.md) and the Music terms in
[glossary.md](../../wiki/glossary.md). Needs briefs 25 and 26.

The owner chose for Discord and atrium's page to be **two remotes for the same
Player**. In Discord, everything sits under one `/jukebox` command with
subcommands, so the picker gains one entry next to the 24 games and tools.
**Anyone in the guild may use it.** The bot **never posts on its own**: no
now-playing announcements. People ask with `/jukebox nowplaying` or look at the
page.

Every subcommand goes through atrium. The bot changes nothing locally. Atrium
then sends the matching command down the long-poll, which brief 26 executes.

The atrium routes this brief calls, restated from atrium brief 81. Errors are
`{error: "CODE"}`.
- `GET /jukebox/tracks?q=` returns `Track[]` in Playlist order, where a `Track`
  is `{id, title, artist, album, trackNumber, durationSeconds}`.
- `GET /jukebox/players/:guildId` returns the `Player`:
  - `online` and `state`;
  - `voiceChannel` and `voiceChannels`;
  - `track`, `positionMs` and `positionAt`;
  - `shuffle` and `repeat`;
  - `queue`, as `[{id, track, addedBy: {kind, name}, addedAt}]`;
  - `upcoming`.
  
  An unknown guild returns 404 `PLAYER_NOT_FOUND`.
- `POST /jukebox/players/:guildId/control` returns the `Player`. The body is one
  of:
  - `{action: "play" | "pause" | "resume" | "next" | "previous" | "stop" | "leave"}`;
  - `{action: "join", channelId}`;
  - `{action: "playTrack", bookId}`.
  
  An offline bot returns 409 `PLAYER_OFFLINE`.
- `PATCH /jukebox/players/:guildId/settings` takes `{shuffle?, repeat?}`.
- `POST /jukebox/players/:guildId/queue` takes
  `{bookId, at: "end" | "next", addedBy: {name}}`. The bot **must** send
  `addedBy.name`, the invoker's display name. A non-audio id returns 400
  `NOT_A_TRACK`.

## What to do

1. **The subcommands of `/jukebox`:**
   - `play track:<autocomplete> [next:boolean]` adds the Track to the Queue, at
     the end, or next if `next` is true.
     - If the bot is not in a voice channel, join the invoker's first. If the
       invoker isn't in one either, answer ephemerally: "Join a voice channel
       first, or use `/jukebox join`."
     - If the Player is idle, also send `play`.
   - `skip` sends `next`. `previous`, `pause`, `resume` and `stop` send the
     action of the same name.
   - `join` joins the invoker's current voice channel, and `leave` leaves.
   - `shuffle on:<boolean>` and `repeat mode:<off|one|all>` change the settings.
   - `nowplaying` shows the title, artist, album, and elapsed over total time.
   - `queue` shows now playing plus the first 10 Queue entries, each with who
     added it, and a count of the rest.
2. **Autocomplete** for `play track`. Discord allows 3 seconds.
   - Cache `GET /jukebox/tracks` for 60 seconds and filter locally on title,
     artist and album, case-insensitive.
   - Return up to 25 choices, labelled "Title · Artist" and cut to 100
     characters. Each choice's value is the Track id.
   - If atrium is unreachable, return an empty list. Never throw.
3. **Replies.** Successful controls get a short public reply ("Skipped.",
   "Added *Title* to the queue."). Discord already shows who ran the command.
   `queue`, `nowplaying` and every error reply are ephemeral. The errors:
   - **Not configured:** "The Jukebox isn't set up on this bot."
   - **Sign-in failed or forbidden:** "The Jukebox can't sign in to atrium. The
     owner has to check its account."
   - **Unreachable:** "Atrium is unreachable right now."
   - **`PLAYER_OFFLINE`:** "The player is offline."
4. **Help.** Add a Music group, so `/help` lists `/jukebox` and its
   subcommands, not "Other".
5. **Docs** in `docs/discord/jukebox/README.md`:
   - what the Jukebox is, and that atrium's page is the other remote;
   - every subcommand;
   - the four `JUKEBOX_*` variables, and the Ward account with its `jukebox`
     grant (atrium's brief 80 owner steps, described in words);
   - `jukebox-session.json`;
   - triage, using brief 26's notes: the dependency report, sign-in failed,
     forbidden, unreachable, and the bot not joining.
   
   Then add a row in `docs/discord/README.md` and run the docs-site sync script.
6. **Register.** Run `npm run discord:register` on the dev application.
